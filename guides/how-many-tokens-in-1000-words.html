How many tokens are in 1,000 words?

For ordinary English prose, 1,000 words is often in the rough neighborhood of 1,300–1,500 tokens, but there is no universal conversion. The tokenizer and the exact text matter.

Practical rule: use a token estimator for planning, then use the target model’s tokenizer or actual API usage when exact billing or context limits matter.

Why “words to tokens” is not a fixed conversion

Language models do not normally bill by ordinary human word count. A tokenizer breaks text into smaller units that may be whole words, word fragments, punctuation, or other pieces. That means “unusual-looking” text can consume more or fewer tokens than its word count suggests.

What changes the estimate?

Text length, punctuation, whitespace, vocabulary, language, emoji, URLs, and code all affect tokenization. Code can be particularly different from prose because punctuation and identifiers are structurally important. Non-English text can also behave differently from the simple English heuristics people memorize.

A better budgeting method

Start with a rough estimate, add a safety margin, and measure real usage once you have a representative sample. For example, if a workflow appears to use about 5,000 input tokens per request, budget above that number until you have enough production measurements to replace the assumption.

FAQ

Is 1,000 words exactly 1,333 tokens?

No. That is a rough planning ratio, not a law of nature. Two passages with the same word count can tokenize differently.

Should I use tokens or words for pricing?

Use tokens for a token-priced API. Word count is useful for drafting and editorial planning, but it is not a billing unit.
